## Foldfit стабилизирован, facet-light принят, 2026-08-31

`foldfit` не меняет набор данных под кандидата ширины. Масштаб шума - один раз по удержанным граням; все `c/s` подгоняются на одних отсчётах с непрерывным `soft-L1`, вес каждого отсчёта положителен. Профиль по `S_GRID` возвращает интервал почти равных решений; шире двух раз - verdict `s_identified=False`.

`analyze` считает `s`, `unres`, отношения к автору и сходимость размеров только по идентифицированным ширинам. Доля остальных - `fold_unident`, чистый храповик без абсолютного порога: renderer не может сделать профиль менее определённым. `fold_tracker` печатает `unid`, такие станции в медиану ширины не идут.

Facet-light из `tools/fold_light_oracle.py` перенесён в `cgr/lightanim.py` только для `AppStarting` и `Wait`. Центр, ширина, support складки - по каноническому кадру; по фазе движутся только `aL,kL,aR,kR` каждой грани. При нулевом support-весе alpha и RGB побайтно прежние. `Hand` - контроль, побайтно совпадает с путём без facet-стадии.

Oracle, 27 фаз × 128/256/512, реальный ratchet:

| курсор | ship → facet-light | итог |
|---|---|---|
| AppStarting | `unident 0.75→0.75`, `s=0.60`, `notch 0.550→0.682` | без долга и FAIL |
| Wait | `unident 0.65→0.55`, `s=0.60`, `notch 0.259→0.287` | без регрессии; notch-долг виден |
| Hand (oracle-контроль) | `unident 0.60→0.60`, `s=0.60`, `notch 0.302→0.311` | новых FAIL нет; production без изменений |

Baseline переснят после раздельного аудита прибора и renderer. Не-fold acceptance-метрики на месте; у Wait сдвинулись только два диагностических `legacy_jitter_*`, PASS/FAIL не решают. Selftest, analyze 32..512, сборка всех платформ зелёные; протокол и основания метода - NEXT.md 72.

## Складку меряют заново, 2026-08-22

Старый `_fold_track` искал тёмную линию (самый тёмный пиксель строки + prominence). Автор её не рисовал: его сечение - переход между двумя уровнями граней с неглубокой зарубкой; его кадры старым прибором - `unmeasured` везде. Цели `fold_gap`/`wander`/`jag`/`luma_step` были догадками без эталона.

Новый прибор `tools/foldfit.py`: сечение по нормали к хорде, две грани отдельными робастными прямыми, детренд, ступень `tanh` по сетке. Один код у `tools/fold_tracker.py` (человеку) и `analyze` (гейту). Приёмка: `fold_cover`, `fold_unres`, `fold_s_*`, `fold_curv`, `fold_step`, `fold_notch`, `fold_jitter`, отдельный класс `inner_tip`. Калибровка по автору: `s = 0.60` LU на 128/256/512, `unres = 0`, зарубка 4-5 уровней.

`legacy_fold_*` и `legacy_inner_jitter` меряются, печатаются, пишутся в baseline, PASS/FAIL не решают.

Прибор смотрит на продукт, не на промежуточное представление (NEXT.md 50). Hand, Wait, AppStarting отгружают 27 кадров, зажжённых с одного канонического рендера; `frame_image` по девяти авторским индексам не отгружается нигде (его контракт складки мерил до 2026-08-22). Вход `product_cycle` - кадры с фазами; эталон на дробной фазе `author_at` - четыре гармоники по девяти авторским отсчётам.

## После v1.1.0: две ветки, не четыре долга

Решение владельца 2026-08-21 (лестница H/J, NEXT.md 45): складка и остаточный профиль яркости у остриёв - одна задача. Обе живут вдоль хорды и читают одни пиксели, поэтому две стадии будут конфликтовать. Владелец - `_tip_relight` (уже есть модель жёлоба вдоль хорды).

- **`fold-relight`** - после закрытия `fold-tracker` (2026-08-22) осталась только продольная половина: уровень света вдоль хорды, остаток +2.7..+8.1 у клиньев. Ничего не блокирует. `fold_gap`/`wander`/`jag` больше не цели: форма складки у шести клиньев авторская (NEXT.md 51), поперечным сечением владеет `_fold_restep`.
- **`no-ring`** - кольцо NO, локально по альфе, контуру и цвету; с моделью клиньев не пересекается. Долг `NO[7] delta_e 5.972` закрыт (см. раздел про знак запрета). Остаток гейта после переснятия baseline 2026-08-29, `NO[5] delta_e 5.54`, - другой кадр, к этому разделу не относится (см. ниже).

`_tip_level` - временное консервативное решение: одно число на полосу, складку не трогает, закрывает видимый дефект. Когда `_tip_relight` научится владеть уровнем, `_tip_level` **удаляется**, второй механизм поверх не наращивать.
