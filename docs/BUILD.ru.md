# Сборка Chrome Glass Remastered

[In English](BUILD.md) · [назад к README](../README.ru.md) · [что внутри пакетов](DETAILS.ru.md)

Все AI-мастера уже закоммичены, поэтому для обычной сборки не нужны ни GPU, ни torch.

```sh
pip install -r requirements.txt
python3 -m cgr.build
```

Скрипт пересобирает `dist/`, `packages/` и превью, а в конце сверяет результат с оригиналом (альфа, насыщенность, тайминг) и ругается, если что-то поехало.

По желанию: видеокарта с CUDA ускоряет сборку и `tools/analyze.py` в несколько раз (около 3 минут против 10 на 12 ядрах, гейт - 1,5 минуты). Пиксели те же, что на CPU: маски, расстояния и ресэмплы совпадают побитово, подгонки складки - до 1e-6 с теми же решениями (`python tools/gpu_parity.py`).

```sh
pip install -r requirements-gpu.txt
CGR_BACKEND=gpu python3 -m cgr.build
```

Без `CGR_BACKEND=gpu` torch не импортируется вовсе.

Умолчания щадящие: процессы расчёта идут с приоритетом ниже обычного и их не больше шести, так что за компьютером можно работать во время сборки. Больше процессов быстрее не делает: видеокарта и ядра общие, десять воркеров дали то же время, что шесть.

| Переменная | Что делает |
|---|---|
| `BUILD_SERIAL=1` | считает в одно ядро вместо всех |
| `ALLOW_METRIC_WARN=1` | выпускает несмотря на предупреждение о дрейфе |
| `CGR_BACKEND=gpu` | тяжёлые стадии считает на GPU (по умолчанию `cpu`) |
| `CGR_GPU_WORKERS=N` | процессов на одну видеокарту (по умолчанию половина ядер, не больше 6) |
| `CGR_GPU_MEM_MB=N` | потолок видеопамяти на процесс (по умолчанию 1024) |
| `CGR_GPU_CHUNK_MB=N` | размер одного временного тензора (по умолчанию 48) |
| `CGR_GPU_FIT_MB=N` | то же для подгонки ширины складки: она упирается в запуски ядер и любит крупные куски (по умолчанию 300) |
| `CGR_NICE=0` | не занижать приоритет GPU-воркеров (Windows) |
| `CGR_WEBP_METHOD=N` | усилие кодировщика webp для анимаций в README: 4 (по умолчанию, секунды) или 6 (самые маленькие файлы, около двух минут на полосу) |
| `CGR_JOB_LOG=1` | печатать время каждого кадра прогрева |

`dist/original/Chrome Glass (2006)/` - нетронутый набор 2006 года, пересобранный как эталон для сверки. Он сознательно только локальный: не пакуется и не попадает в релизы.

## Что за что отвечает

| Папка / файл | Что там |
|---|---|
| `art/orig/` | нетронутая графика 2006 года, 32 px - эталон для сверки |
| `art/ai/` | AI-апскейл до 128 px, из него `trace.py` берёт формы |
| `art/ai512/` | цветной AI-мастер, нативное разрешение |
| `art/aialpha/` | AI-апскейл прозрачности, отдельно от цвета |
| `data/traced.json` | векторные контуры из `trace.py` |

Порядок сборки:

```
art/ -> trace.py -> data/traced.json -> hybrid.py + glyphs.py -> build.py -> curlib.py / vectorlib.py
```

Пара мелочей нарисована вручную в `cursors.py`, а не найдена трассировщиком - например, точка под знаком «?» у Help: она стоит отдельно от стрелки, и автоматика её не видит.

## Проверка рендера

Собственный гейт `cgr/build.py` смотрит только на медианную альфу и насыщенность. Всё остальное - силуэт, который меняет размер вместе с размером отрисовки, складку, разбитую на куски, цвет, ушедший от авторского, анимацию, которая спешит, - меряет `tools/analyze.py`, прямо по `hybrid.frame_image`, без сборки:

```
python tools/analyze.py --check data/metrics-baseline.json --jobs 8
```

`data/metrics-baseline.json` - это то, где набор стоит сегодня, и он в репозитории. Значение, которое не дотягивает до цели, но не хуже этого файла, печатается как долг и сборку не валит; значение, ушедшее от цели дальше, валит сразу. `--fast` - короткая лестница из трёх ступеней для итераций; обычная лестница уже включает 512 и на ней идёт приёмка, `--full` оставлен ради старых скриптов, но сейчас ничего не добавляет, `--ratchet FILE` переписывает базу, когда улучшение состоялось.

`tools/selftest.py` подсаживает по дефекту каждого вида и требует, чтобы отвечающая за него метрика сдвинулась. Гонять до того, как поверить чистому гейту: метрика, которая не умеет упасть, покажет чистый прогон на сломанном курсоре.

`tools/loop.py diagnose` группирует отказы по артефактам и называет следующий шаг; `checkpoint`, `rollback` и `progress` ведут `docs/dev/PROGRESS.md` и `docs/dev/DEAD_ENDS.md`.

## Ассеты для превью

`cgr/build.py` заодно генерирует всё, что вставлено в README:

| Файл | Что это |
|---|---|
| `assets/preview.png` | витрина из 15 плиток |
| `assets/comparison.png` | растянутый оригинал 2006 против ремастера в нативных 512 px |
| `assets/animations.webp` | все пять анимированных курсоров рядом |
| `assets/<имя>.webp` | каждый анимированный курсор отдельно |
| `assets/<имя>.gif` | то же самое для мест, где анимированный webp до сих пор не принимают (форумы, DeviantArt, Reddit). В репозитории на них никто не ссылается, они лежат, чтобы залить руками. |

Двух курсоров в витрине нет намеренно. **Hand** и **Handwriting** в оригинале 2006 года - тот же силуэт стрелки, что и **Arrow**, отличаются только межкадровым блеском, поэтому статичная плитка просто дублировала бы Arrow; вместо этого их видно в движении в `assets/animations.webp`. **Arrow_Down** попал в `WIN_UNSHIPPED`: он собирается, но не пакуется, и показывать его значило бы рекламировать курсор, которого нет в скачанном архиве.

`assets/social-preview.png` - обложка репозитория. Её делает `tools/gen_social_preview.py`, который сборка никогда не вызывает, поэтому файл закоммичен, а не генерируется заново.

## Пересчитать AI-апскейлы (по желанию)

Нужно, только если хотите посчитать апскейлы заново, а не брать готовые из репозитория. Единственный шаг, для которого нужны видеокарта и torch (PyTorch):

```sh
pip install -r requirements-ai.txt

python3 tools/upscale128.py     # art/orig -> art/ai       (база 128 px)
python3 tools/upscale512.py     # art/ai   -> art/ai512    (мастер цвета)
python3 tools/upscale_alpha.py  # art/orig -> art/aialpha  (мастер альфы)
```

Нужен один файл весов - `RealESRGAN_x4plus_anime_6B.pth` (~18 МБ, под иллюстрации), положите его в `weights/` сами (`upscale_lib.load_model` грузит локально, без скачивания). Результаты уже закоммичены, поэтому остальным этим заниматься не нужно.
