# Что внутри пакетов

[In English](DETAILS.md) · [к README](../README.ru.md) · [собрать самому](BUILD.ru.md)

Всё, что не поместилось в README: что реально получает каждая платформа, откуда взялись числа, как снять тему полностью и что не работает.

Проверено на Windows 11 Pro 25H2 (сборка 26200) и Debian 13 (trixie), GNOME на X11, гибрид Intel+NVIDIA. Cape для macOS собирается и проходит проверку на каждом релизе, но на живом железе его никто не применял. CI собирает на ubuntu-latest, Python 3.12.

## Что не работает

Прочитайте до того, как заводить issue.

- **macOS не проверялась и покрыта частично.** Сопоставлено 36 идентификаторов курсора, остальные остаются системными. Анимированы Wait и Busy. Приложения со своими курсорами перекрывают Mousecape целиком.
- **Анимация на Windows останавливается на 128 px.** Windows не принимает `.ani`, в кадре которого изображений больше чем на ~70 КБ, а одно изображение 256 px уже больше. Поэтому на самых крупных указателях пять анимированных курсоров мягче статических, которые доходят до 256.
- **У `Install.inf` нет пункта Uninstall.** Windows 10/11 регистрируют для `.inf` ровно один пункт меню, Install. Удаление - ручным путём, он описан ниже.
- **Голубая `Arrow_Down` есть только на Linux.** Ни один слот схемы Windows на неё не указывает, так что в пакете Windows она стоила бы каждому 407 КБ в `%SystemRoot%` ради курсора, который нельзя выбрать. На Linux она показывается у контекстного меню и при перетаскивании с копированием или ссылкой.

## Windows

17 слотов схемы в порядке реестра, включая слоты **Pin** и **Person** из Windows 10/11, которых в наборе 2006 года не было. Оба нарисованы заново в стиле оригинала.

| | Размеры | Кадры |
|---|---|---|
| Статика `.cur` | 32, 40, 48, 56, 64, 96, 128, 256 | - |
| Анимация `.ani` | 128, 96, 64, 56, 48, 40, 32 | Кадры и тайминг автора: AppStarting, Hand, Wait по 9, Handwriting 9, NO 11. |

256 px - потолок самого формата `.cur`: ширина и высота в `ICONDIRENTRY` занимают по одному байту, 256 кодируется нулём. Выше там просто нечего поставить.

Установленная схема занимает около 2.5 МБ в `%WINDIR%\Chrome Glass Remastered`. `Install.inf` пишет схему только в HKCU: вкладка "Указатели" сливает пользовательскую и машинную ветки, поэтому запись в обе показала бы схему дважды всем - ради редкого случая, когда админ ставит её не себе.

### Полное удаление

Первый шаг делайте до всего остального, иначе Windows останется со ссылками на файлы, которые вы собираетесь удалить.

1. **Дополнительные параметры мыши → Указатели**: выберите **Chrome Glass Remastered**, нажмите **Удалить**, затем переключитесь на **Стандартная Windows** и нажмите **ОК**. Это чистит запись в реестре.
2. Дальше либо удалите папку `%WINDIR%\Chrome Glass Remastered` вручную с правами администратора, либо выполните секцию удаления из .inf напрямую:

```
rundll32.exe setupapi,InstallHinfSection DefaultUninstall 132 "<полный путь>\Install.inf"
```

## Linux

16 ролей курсора, 114 имён в `cursors/`. Лишние имена - псевдонимы: читаемые вроде `left_ptr`, `pointer`, `nwse-resize`, и устаревшие MD5-хексы вроде `9d800788f1b08800ae810202380a0822`.

Хексы здесь не для красоты. Firefox, Chromium/Electron, Java и старый GTK2 спрашивают курсоры именно по ним и больше никак. Без них указатель молча уезжает в тему-запасник посреди перетаскивания или при наведении на ссылку - самый заметный способ для темы Xcursor выглядеть недоделанной. Каждый хекс поставлен по тому каноническому имени, с которым его связывает Bibata, а не по памяти: хекс под чужой ролью хуже, чем отсутствующий, потому что тема-запасник хотя бы нарисовала бы правильную форму.

| | Размеры |
|---|---|
| Статика | 32, 40, 48, 56, 64, 96, 128, 256, 384, 512 |
| Анимация | 32, 40, 48, 56, 64, 96, 128, 256, 384 |

512 остаётся только статикой: девять кадров в нативных 512 - это около 1 МБ сырого ARGB на кадр ради самого редкого случая, какой бывает.

**Анимации идут в авторском темпе ~20 fps намеренно.** Xcursor меняет кадры без синхронизации с композитором, поэтому темп 60 fps периодически расходится с разверткой 60-герцевой панели и даёт мерцание - воспроизводилось на GNOME/Mutter под X11 на гибриде Intel+NVIDIA. На авторском темпе не воспроизводится. `.ani` для Windows идут в том же темпе: на 60 fps превью во вкладке «Указатели» дёргалось и тормозило.

Распакованная тема занимает около 78 МБ, из них 8 МБ - hyprcursor. Внутри архива и .deb псевдонимы лежат симлинками, а не копиями, и это экономит примерно 85% объёма.

Пакет .deb регистрирует в `update-alternatives` как `x-cursor-theme` свой `cursor.theme`, который наследует эту тему, с приоритетом 20, ниже 90 у Adwaita: тема становится выбором в `sudo update-alternatives --config x-cursor-theme`, а не захватывает систему, и при удалении регистрация снимается. До 1.1.0 регистрировался `index.theme`, у которого `Inherits=Adwaita`, и такой выбор приводил к Adwaita; обновление переносит его на новую запись. `PKGBUILD` в репозитории привязан к предыдущему тегу и несёт `sha256sums=SKIP`, чтобы собиралось из голого клона; копия, приложенная к релизу, пришпилена к его тегу и содержит настоящую контрольную сумму.

Для одного сеанса или одного приложения задайте `XCURSOR_THEME="Chrome Glass Remastered"` до его запуска.

**Hyprcursor.** В той же папке темы лежат `manifest.hl` и `hyprcursors/`: те же 16 ролей, размеры и кадры, но в PNG. Hyprland берёт их вместо `cursors/` и масштабирует между нашими размерами сам. Остриё у центровых курсоров (Cross, IBeam) задаётся долей холста, одной на все размеры, поэтому там оно на пиксель правее и ниже, чем в Xcursor. Имена-хексы в hyprcursor не попадают: по ним спрашивают только клиенты X11.

### Полное удаление

```sh
sudo apt remove chrome-glass-remastered-cursors        # .deb
sudo pacman -R chrome-glass-remastered-cursors         # Arch
rm -rf ~/.icons/"Chrome Glass Remastered"  # ручная установка
```

## macOS

Тем курсора в macOS нет; Mousecape применяет "cape". Включены только идентификаторы с уверенным сопоставлением, всё остальное Mousecape оставляет системным.

Сопоставлено 36: Arrow, IBeam, Move, Wait, Busy (AppStarting), Crosshair и Cell, указывающая, открытая и сжатая рука (Hand), Forbidden, Help, все направления изменения размера курсора и окна (одностороннему достаётся двусторонняя стрелка его оси, как на Linux), а также Copy, Alias, Link, Copy Drag и контекстное меню (голубая Arrow_Down). ArrowCtx не тронут: Mousecape считает его синонимом Arrow и сделал бы голубыми все стрелки. Каждый идёт в масштабах 1, 2, 5 и 10, то есть 32, 64, 160 и 320 px.

Анимированы Wait и Busy, девятью кадрами автора: курсор больше чем из 24 кадров Mousecape не применяет. У cape один `FrameDuration` на курсор, поэтому авторское "проиграть один раз и замереть" он выразить не может: Hand отгружается устоявшимся последним кадром, а не началом прорисовки.

Вернуть системные курсоры: **File → Reset System Cursor** или <kbd>⌘</kbd>+<kbd>R</kbd>. Чтобы cape пережил перезагрузку, включите **Settings → General → Launch at Login** в Mousecape.

## Разбор проблем

**Темы нет в списке или указатель не сменился.** Выйдите из сеанса и войдите снова. Приложения запоминают курсор при запуске, так что перезапустите те, где остался старый.

**Распаковал на Linux, ничего не появилось.** Архив должен лечь как `~/.icons/Chrome Glass Remastered/cursors/`, без лишней папки-обёртки между ними. Проверка: `ls ~/.icons/"Chrome Glass Remastered"/cursors | head`.

**Указатель уезжает в другую тему посреди перетаскивания или на ссылке в Firefox.** Эти запросы идут по устаревшим хекс-именам. В релизных архивах есть все 114 имён, так что проверьте, что у вас именно эта тема, а не её частичная копия.

**Анимации мерцают на X11.** На ~20 fps не должны. Если мерцают, назовите в issue композитор и видеокарту: воспроизводился случай на 60 fps, и его закрыл переход на авторский темп.

**Mousecape сменил курсор не везде.** Откройте **System Settings → Accessibility → Display → Pointer**, сбросьте цвета указателя к стандартным и примените cape ещё раз. Приложения со своими курсорами продолжат рисовать свои.

**Windows: анимированные курсоры мягче стрелки.** Так и есть выше 128 px, см. потолок выше.

## Проверка скачанного

В каждом релизе есть `SHA256SUMS`. На Linux положите его рядом со скачанными файлами:

```sh
sha256sum --ignore-missing -c SHA256SUMS
```

На Windows выполните `Get-FileHash <файл> -Algorithm SHA256` в PowerShell и сравните результат с тем же файлом.

## Как это собрано

Кадры 2006 года остаются эталоном формы, цвета и тайминга. С версии 2.0.0 каждый указатель рисуется из геометрии, а не увеличивается:

1. силуэт автора трассирован в вектор (по апскейлу его кадров до 128 px, только ради контура), и на нём строится стеклянная поверхность: ободок со светлым плечом и тёмной кромкой, грани, сходящиеся в складке, внутренний кончик на биссектрисе;
2. тон авторский: снят с его кадра 32 px вдоль контура и по граням, поэтому на 32 px стрелки отличаются от его пикселей на несколько уровней;
3. каждый размер считается заново, 4x4 отсчёта на пиксель в линейном свете, без размытия и апскейла между ними. 32 px рисуется так же; только знак «?» у Help там остаётся из пикселей автора: его штрих там в пиксель-два.

Анимации устроены так же: у Wait и AppStarting контур неподвижен, а свет бежит по нему по девяти ключам автора, и тело переливается так же, как у него; у Handwriting стрелка сжимается, и из её острия растёт стеклянное перо.

В поставляемых курсорах нет ни одного пикселя, нарисованного нейросетью. Цветные AI-мастера, на которых собиралась версия 1.x, удалены из репозитория вместе со старым конвейером.
