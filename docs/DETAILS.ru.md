# Что внутри пакетов

[In English](DETAILS.md) · [к README](../README.ru.md) · [собрать самому](BUILD.ru.md)

Всё, что не поместилось в README: что реально получает каждая платформа, откуда взялись числа, как снять тему полностью и что не работает.

Проверено на Windows 11 Pro 25H2 (сборка 26200) и Debian 13 (trixie), GNOME на X11, гибрид Intel+NVIDIA. Cape для macOS собирается и проходит проверку на каждом релизе, но на живом железе его никто не применял. CI собирает на ubuntu-latest, Python 3.12.

## Что не работает

Прочитайте до того, как заводить issue.

- **macOS не проверялась и покрыта частично.** Сопоставлено двенадцать идентификаторов курсора, остальные остаются системными. Анимирован только Wait. Приложения со своими курсорами перекрывают Mousecape целиком.
- **Анимация на Windows останавливается на 96 px.** Кадр внутри `.ani` не может нести изображение 128 px, Windows отказывается принимать такой файл. Поэтому на крупном указателе пять анимированных курсоров заметно мягче статических, которые доходят до 256.
- **У `Install.inf` нет пункта Uninstall.** Windows 10/11 регистрируют для `.inf` ровно один пункт меню, Install. Удаление - ручным путём, он описан ниже.
- **`Arrow_Down` собирается, но не поставляется.** Ни один слот схемы Windows на него не указывает, так что в пакете он стоил бы каждому 407 КБ в `%SystemRoot%` ради курсора, который нельзя выбрать.

## Windows

17 слотов схемы в порядке реестра, включая слоты **Pin** и **Person** из Windows 10/11, которых в наборе 2006 года не было. Оба нарисованы заново в стиле оригинала.

| | Размеры | Кадры |
|---|---|---|
| Статика `.cur` | 32, 48, 64, 96, 128, 256 | - |
| Анимация `.ani` | 96, 64, 48, 32 | AppStarting, Hand, Wait: 27 кадров на 60 fps. Handwriting: 9. NO: 11. У обоих сохранён авторский покадровый тайминг. |

256 px - потолок самого формата `.cur`: ширина и высота в `ICONDIRENTRY` занимают по одному байту, 256 кодируется нулём. Выше там просто нечего поставить.

Установленная схема занимает около 11.3 МБ в `%WINDIR%\Chrome Glass Remastered`. `Install.inf` пишет схему только в HKCU: вкладка "Указатели" сливает пользовательскую и машинную ветки, поэтому запись в обе показала бы схему дважды всем - ради редкого случая, когда админ ставит её не себе.

### Полное удаление

Первый шаг делайте до всего остального, иначе Windows останется со ссылками на файлы, которые вы собираетесь удалить.

1. **Дополнительные параметры мыши → Указатели**: выберите **Chrome Glass Remastered**, нажмите **Удалить**, затем переключитесь на **Стандартная Windows** и нажмите **ОК**. Это чистит запись в реестре.
2. Дальше либо удалите папку `%WINDIR%\Chrome Glass Remastered` вручную с правами администратора, либо выполните секцию удаления из .inf напрямую:

```
rundll32.exe setupapi,InstallHinfSection DefaultUninstall 132 "<полный путь>\Install.inf"
```

## Linux

15 ролей курсора, 114 имён в `cursors/`. Лишние имена - псевдонимы: читаемые вроде `left_ptr`, `pointer`, `nwse-resize`, и устаревшие MD5-хексы вроде `9d800788f1b08800ae810202380a0822`.

Хексы здесь не для красоты. Firefox, Chromium/Electron, Java и старый GTK2 спрашивают курсоры именно по ним и больше никак. Без них указатель молча уезжает в тему-запасник посреди перетаскивания или при наведении на ссылку - самый заметный способ для темы Xcursor выглядеть недоделанной. Каждый хекс поставлен по тому каноническому имени, с которым его связывает Bibata, а не по памяти: хекс под чужой ролью хуже, чем отсутствующий, потому что тема-запасник хотя бы нарисовала бы правильную форму.

| | Размеры |
|---|---|
| Статика | 32, 48, 64, 96, 128, 256, 384, 512 |
| Анимация | 32, 48, 64, 96, 128, 256, 384 |

512 остаётся только статикой: девять кадров в нативных 512 - это около 1 МБ сырого ARGB на кадр ради самого редкого случая, какой бывает.

**Анимации идут в авторском темпе ~20 fps намеренно.** Xcursor меняет кадры без синхронизации с композитором, поэтому темп 60 fps периодически расходится с разверткой 60-герцевой панели и даёт мерцание - воспроизводилось на GNOME/Mutter под X11 на гибриде Intel+NVIDIA. На авторском темпе не воспроизводится. В `.ani` для Windows интерполированные 60 fps остались, оттуда жалоб не было.

Распакованная тема занимает около 64 МБ. Внутри архива и .deb псевдонимы лежат симлинками, а не копиями, и это экономит примерно 85% объёма.

Пакет .deb регистрирует тему в `update-alternatives` с приоритетом 20 - намеренно ниже осознанного выбора пользователя - и снимает регистрацию при удалении. `PKGBUILD` в репозитории привязан к предыдущему тегу и несёт `sha256sums=SKIP`, чтобы собиралось из голого клона; копия, приложенная к релизу, пришпилена к его тегу и содержит настоящую контрольную сумму.

Для одного сеанса или одного приложения задайте `XCURSOR_THEME="Chrome Glass Remastered"` до его запуска.

### Полное удаление

```sh
sudo apt remove chrome-glass-remastered-cursors        # .deb
sudo pacman -R chrome-glass-remastered-cursors         # Arch
rm -rf ~/.local/share/icons/"Chrome Glass Remastered"  # ручная установка
```

## macOS

Тем курсора в macOS нет; Mousecape применяет "cape". Включены только идентификаторы с уверенным сопоставлением, всё остальное Mousecape оставляет системным.

Сопоставлено двенадцать: Arrow, IBeam, Move, Wait, Crosshair, Pointing Hand, Forbidden, Help и четыре направления изменения размера. Каждый идёт в масштабах 1, 2 и 5, то есть 32, 64 и 160 px.

Анимирован только Wait. У cape один `FrameDuration` на курсор, поэтому авторское "проиграть один раз и замереть" он выразить не может: Hand отгружается устоявшимся последним кадром, а не началом прорисовки.

Вернуть системные курсоры: **File → Reset System Cursor** или <kbd>⌘</kbd>+<kbd>R</kbd>. Чтобы cape пережил перезагрузку, включите **Settings → General → Launch at Login** в Mousecape.

## Разбор проблем

**Темы нет в списке или указатель не сменился.** Выйдите из сеанса и войдите снова. Приложения запоминают курсор при запуске, так что перезапустите те, где остался старый.

**Распаковал на Linux, ничего не появилось.** Архив должен лечь как `~/.local/share/icons/Chrome Glass Remastered/cursors/`, без лишней папки-обёртки между ними. Проверка: `ls ~/.local/share/icons/"Chrome Glass Remastered"/cursors | head`.

**Указатель уезжает в другую тему посреди перетаскивания или на ссылке в Firefox.** Эти запросы идут по устаревшим хекс-именам. В релизных архивах есть все 114 имён, так что проверьте, что у вас именно эта тема, а не её частичная копия.

**Анимации мерцают на X11.** На ~20 fps не должны. Если мерцают, назовите в issue композитор и видеокарту: воспроизводился случай на 60 fps, и его закрыл переход на авторский темп.

**Mousecape сменил курсор не везде.** Откройте **System Settings → Accessibility → Display → Pointer**, сбросьте цвета указателя к стандартным и примените cape ещё раз. Приложения со своими курсорами продолжат рисовать свои.

**Windows: анимированные курсоры мягче стрелки.** Так и есть, см. потолок 96 px выше.

## Проверка скачанного

В каждом релизе есть `SHA256SUMS`. На Linux положите его рядом со скачанными файлами:

```sh
sha256sum --ignore-missing -c SHA256SUMS
```

На Windows выполните `Get-FileHash <файл> -Algorithm SHA256` в PowerShell и сравните результат с тем же файлом.

## Как это собрано

Кадры 2006 года остаются эталоном формы, цвета и тайминга. При сборке сходятся три входа:

1. AI-мастер цвета, настроенный под иллюстрации, нативный до 512 px;
2. отдельно увеличенный мастер альфы, чтобы стекло сохранило прозрачность;
3. трассированный в вектор силуэт, который растрируется заново в каждом поставляемом размере.

Оба мастера посчитаны один раз и лежат в репозитории, поэтому обычная сборка не требует ни видеокарты, ни torch. Вектор относится к конвейеру, а не к формату поставки: устанавливаются растровые курсоры в размерах из таблиц выше.

Команды сборки, гейт качества и пересчёт мастеров: **[BUILD.ru.md](BUILD.ru.md)**.
